1. WHAT IS THIS PROJECT?
--------------------------------------------------------------------------------
This is a full-stack Task Management application ("TaskFlow") built with:
  1. Backend: Laravel 12 REST API connected to MySQL/MariaDB (via XAMPP).
  2. Frontend: Flutter 3.29 client app running on Mobile, Chrome Web, and Desktop.

The app allows users to perform full CRUD operations:
  • View all tasks with real-time statistics (remaining vs. completed).
  • Filter tasks (All / Pending / Completed) and search by keyword.
  • Create tasks with title, optional description, and target due date.
  • Edit existing tasks and change status.
  • Mark tasks completed with a single tap toggle.
  • Delete tasks with a safety confirmation dialog.

3. HOW THE BACKEND WORKS (LARAVEL 12)
--------------------------------------------------------------------------------
A. Database Schema (`database/migrations/...create_tasks_table.php`):
   • `id`: Auto-incrementing primary key.
   • `title`: string(255), required.
   • `description`: text, nullable (optional).
   • `status`: enum('pending', 'completed'), defaults to 'pending'.
   • `due_date`: date, nullable ('YYYY-MM-DD').
   • `created_at` & `updated_at`: timestamps.

B. Eloquent Model (`app/Models/Task.php`):
   • Defines `$fillable = ['title', 'description', 'status', 'due_date']` to prevent 
     mass-assignment vulnerabilities.
   • Defines `$casts` for `due_date` to ensure consistent `YYYY-MM-DD` formatting.

C. Validation with Form Requests (`app/Http/Requests/`):
   • `StoreTaskRequest`: Ensures `title` is provided and strings do not exceed 255 chars.
   • `UpdateTaskRequest`: Uses the `'sometimes'` rule so partial updates (like PATCH 
     for only toggling status) succeed without needing to re-send the title.
   • When validation fails, Laravel automatically responds with HTTP 422 and a 
     structured JSON error map.

D. Controller Endpoints (`app/Http/Controllers/Api/TaskController.php`):
   • `index()`   -> GET /api/tasks        -> Returns all tasks, newest first (200).
   • `show()`    -> GET /api/tasks/{id}   -> Returns single task or 404 JSON.
   • `store()`   -> POST /api/tasks       -> Validates & creates new task (201).
   • `update()`  -> PATCH /api/tasks/{id} -> Updates specified fields (200).
   • `destroy()` -> DELETE /api/tasks/{id}-> Removes task & returns confirmation (200).

E. Clean JSON Exception Handling & CORS:
   • In `bootstrap/app.php`, any 404 ModelNotFoundException returns a clean JSON 
     payload (`{"message": "Resource not found."}`) instead of raw HTML error pages.
   • In `config/cors.php`, API routes have CORS enabled so Flutter Web and emulators 
     can connect without browser origin blocks.


4. HOW THE FRONTEND WORKS (FLUTTER 3.29)
--------------------------------------------------------------------------------
A. Configuration (`lib/config/api_config.dart`):
   • Houses the backend endpoint (`http://127.0.0.1:8000/api` for Chrome/Windows 
     desktop, and `http://10.0.2.2:8000/api` for Android Emulator).

B. Data Model (`lib/models/task.dart`):
   • Strong typing: Encapsulates id, title, description, status, and dueDate.
   • `fromJson()` correctly maps Laravel's `due_date` (snake_case) to Dart camelCase.
   • Helper getter `isCompleted` returns true if status == 'completed'.

C. API Service Layer (`lib/services/api_service.dart`):
   • Sends `Accept: application/json` on all requests so Laravel always replies with JSON.
   • Implements strict HTTP status validation and safe timeouts (15 seconds).
   • Throws typed `ApiException` carrying status code and descriptive server message.

D. UI & UX Architecture:
   • Main Theme (`lib/main.dart`):
     Styled with modern Material 3, custom typography via Google Fonts (Plus Jakarta Sans), 
     clean slate background (`#F8FAFC`), and vibrant Indigo/Violet accents (`#6366F1`).
   • Task List Dashboard (`lib/screens/task_list_screen.dart`):
     - Workspace Banner: Displays pending count, completion ratio, and circular percentage graphic.
     - Live Search Bar: Real-time keyword filtering across titles and descriptions.
     - Filter Chips: Instant switching between "All", "Pending", and "Completed".
     - Robust States:
       * Loading State: Centered modern spinner with label.
       * Empty State: Illustrated empty inbox with guidance to add a task.
       * Error State: Clear error icon, message, and one-tap "Retry" button.
       * Pull-to-Refresh: Swipe down to reload from the backend.
   • Reusable Task Card (`lib/widgets/task_card.dart`):
     - Interactive circular check button with animated appearance.
     - Subtle status badge (Emerald Green for Completed, Amber for Pending).
     - Overdue date warning chip (turns red if due date has passed).
     - Delete action with confirmation modal dialog.
   • Reusable Task Form (`lib/screens/task_form_screen.dart` & `task_form_fields.dart`):
     - Single form handling both Create and Edit operations seamlessly.
     - Interactive DatePicker with clear button.
     - Segmented status selector button.
     - In-form client validation before any network request is initiated.


5. HOW TO RUN AND DEMONSTRATE
--------------------------------------------------------------------------------
Step 1: Make sure MySQL is running in XAMPP Control Panel.

Step 2: Start the Laravel API Server
  Open a terminal and run:
    cd c:\xampp\htdocs\axolotls_assignment\task_manager_api
    php artisan serve --host=0.0.0.0 --port=8000
  Keep this terminal open.

Step 3: Run the Flutter App
  Open a second terminal and run:
    cd c:\xampp\htdocs\axolotls_assignment\task_manager_app
    flutter run -d chrome
  (Or `flutter run -d windows` if preferred).

Step 4: Running Automated Tests
  • To run backend tests:
    cd c:\xampp\htdocs\axolotls_assignment\task_manager_api
    php artisan test
    (All 17 tests pass with 44 assertions)

  • To run frontend tests:
    cd c:\xampp\htdocs\axolotls_assignment\task_manager_app
    flutter test
    (All widget tests pass)

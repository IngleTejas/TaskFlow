3.5  FORM REQUEST CLASSES
──────────────────────────
Generate:
  php artisan make:request StoreTaskRequest
  php artisan make:request UpdateTaskRequest

StoreTaskRequest.php
  public function authorize(): bool { return true; }

  public function rules(): array
  {
      return [
          'title'       => ['required', 'string', 'max:255'],
          'description' => ['nullable', 'string'],
          'status'      => ['nullable', 'in:pending,completed'],
          'due_date'    => ['nullable', 'date_format:Y-m-d', 'after_or_equal:today'],
      ];
  }

UpdateTaskRequest.php
  public function authorize(): bool { return true; }

  public function rules(): array
  {
      return [
          'title'       => ['sometimes', 'required', 'string', 'max:255'],
          'description' => ['nullable', 'string'],
          'status'      => ['nullable', 'in:pending,completed'],
          'due_date'    => ['nullable', 'date_format:Y-m-d'],
      ];
  }

  NOTE: 'sometimes' on 'title' in UpdateTaskRequest means the rule only fires
  if the key is present in the request — allows PATCH partial updates.

  NOTE on validation failure (422): Laravel's FormRequest automatically returns
  HTTP 422 Unprocessable Content with a JSON body when validation fails:
  {
    "message": "The title field is required.",
    "errors": { "title": ["The title field is required."] }
  }
  No manual try/catch is needed for validation errors.

3.6  CONTROLLER
────────────────
Generate:
  php artisan make:controller Api/TaskController --api

File: app/Http/Controllers/Api/TaskController.php

  <?php
  namespace App\Http\Controllers\Api;

  use App\Http\Controllers\Controller;
  use App\Http\Requests\StoreTaskRequest;
  use App\Http\Requests\UpdateTaskRequest;
  use App\Models\Task;
  use Illuminate\Http\JsonResponse;

  class TaskController extends Controller
  {
      // GET /api/tasks
      public function index(): JsonResponse
      {
          $tasks = Task::latest()->get();
          return response()->json($tasks, 200);
      }

      // GET /api/tasks/{task}
      public function show(Task $task): JsonResponse
      {
          return response()->json($task, 200);
      }

      // POST /api/tasks
      public function store(StoreTaskRequest $request): JsonResponse
      {
          $task = Task::create($request->validated());
          return response()->json($task, 201);
      }

      // PUT/PATCH /api/tasks/{task}
      public function update(UpdateTaskRequest $request, Task $task): JsonResponse
      {
          $task->update($request->validated());
          return response()->json($task->fresh(), 200);
      }

      // DELETE /api/tasks/{task}
      public function destroy(Task $task): JsonResponse
      {
          $task->delete();
          return response()->json(['message' => 'Task deleted successfully.'], 200);
      }
  }

  NOTES:
  • Route model binding ({task}) automatically resolves the Task by id and
    returns 404 JSON if not found — no manual Task::findOrFail needed.
  • $task->fresh() after update() ensures the returned JSON reflects the
    actual saved state (including any casts / mutators applied at DB level).
  • DELETE returns 200 with a message body (not 204 No Content) so Flutter
    can easily check the response without special empty-body handling.

5.4  TASK MODEL (lib/models/task.dart)
───────────────────────────────────────
  class Task {
    final int id;
    final String title;
    final String? description;
    final String status;        // "pending" | "completed"
    final String? dueDate;      // "YYYY-MM-DD" or null
    final String createdAt;
    final String updatedAt;

    const Task({
      required this.id,
      required this.title,
      this.description,
      required this.status,
      this.dueDate,
      required this.createdAt,
      required this.updatedAt,
    });

    bool get isCompleted => status == 'completed';

    factory Task.fromJson(Map<String, dynamic> json) {
      return Task(
        id:          json['id'] as int,
        title:       json['title'] as String,
        description: json['description'] as String?,
        status:      json['status'] as String,
        dueDate:     json['due_date'] as String?,
        createdAt:   json['created_at'] as String,
        updatedAt:   json['updated_at'] as String,
      );
    }

    Map<String, dynamic> toJson() {
      return {
        'title':       title,
        'description': description,
        'status':      status,
        if (dueDate != null) 'due_date': dueDate,
      };
    }
  }

  CRITICAL: The JSON key from Laravel is "due_date" (snake_case), not
  "dueDate". Always map it explicitly as shown above.

5.5  API SERVICE (lib/services/api_service.dart)
─────────────────────────────────────────────────
  import 'dart:convert';
  import 'package:http/http.dart' as http;
  import '../config/api_config.dart';
  import '../models/task.dart';

  class ApiException implements Exception {
    final int statusCode;
    final String message;
    const ApiException(this.statusCode, this.message);
    @override
    String toString() => 'ApiException($statusCode): $message';
  }

  class ApiService {
    static final _headers = {
      'Content-Type': 'application/json',
      'Accept': 'application/json',         // REQUIRED — forces JSON errors
    };

    static Uri _uri(String path) =>
        Uri.parse('${ApiConfig.baseUrl}$path');

    static Future<http.Response> _safeRequest(
      Future<http.Response> Function() request,
    ) async {
      try {
        final response = await request().timeout(ApiConfig.timeout);
        return response;
      } on Exception catch (e) {
        throw ApiException(0, 'Network error: $e');
      }
    }

    static void _assertSuccess(http.Response res, List<int> expected) {
      if (!expected.contains(res.statusCode)) {
        final body = jsonDecode(res.body) as Map<String, dynamic>;
        throw ApiException(res.statusCode, body['message'] ?? 'Unknown error');
      }
    }

    // GET /api/tasks
    static Future<List<Task>> getTasks() async {
      final res = await _safeRequest(
        () => http.get(_uri('/tasks'), headers: _headers),
      );
      _assertSuccess(res, [200]);
      final List<dynamic> data = jsonDecode(res.body);
      return data.map((j) => Task.fromJson(j)).toList();
    }

    // GET /api/tasks/{id}
    static Future<Task> getTask(int id) async {
      final res = await _safeRequest(
        () => http.get(_uri('/tasks/$id'), headers: _headers),
      );
      _assertSuccess(res, [200]);
      return Task.fromJson(jsonDecode(res.body));
    }

    // POST /api/tasks
    static Future<Task> createTask(Map<String, dynamic> data) async {
      final res = await _safeRequest(
        () => http.post(_uri('/tasks'), headers: _headers, body: jsonEncode(data)),
      );
      _assertSuccess(res, [201]);
      return Task.fromJson(jsonDecode(res.body));
    }

    // PATCH /api/tasks/{id}
    static Future<Task> updateTask(int id, Map<String, dynamic> data) async {
      final res = await _safeRequest(
        () => http.patch(_uri('/tasks/$id'), headers: _headers, body: jsonEncode(data)),
      );
      _assertSuccess(res, [200]);
      return Task.fromJson(jsonDecode(res.body));
    }

    // DELETE /api/tasks/{id}
    static Future<void> deleteTask(int id) async {
      final res = await _safeRequest(
        () => http.delete(_uri('/tasks/$id'), headers: _headers),
      );
      _assertSuccess(res, [200]);
    }
  }

5.6  SCREEN STRUCTURE
──────────────────────
Three screens are sufficient for the MVP:

  (1) TaskListScreen   — default home route
      State: _isLoading (bool), _tasks (List<Task>), _errorMessage (String?)
      On init: call ApiService.getTasks() → populate _tasks
      Displays:
        • Loading state: CircularProgressIndicator centred
        • Error state: error message + retry button
        • Empty state: "No tasks yet. Tap + to create one."
        • Task list: ListView.builder of TaskCard widgets
      FAB: navigates to TaskFormScreen(task: null)
      On each TaskCard: tap → TaskFormScreen(task: task) for edit
      On each TaskCard: checkbox/toggle → ApiService.updateTask(id, {status})
      On each TaskCard: delete icon → confirm dialog → ApiService.deleteTask(id)
      After any mutation: call _loadTasks() to refresh the list

  (2) TaskFormScreen(Task? task)
      Mode: task == null → Create · task != null → Edit
      Fields:
        • Title TextFormField (required, max 255, trimmed before submit)
        • Description TextFormField (optional, multiline)
        • Due Date: read-only TextFormField + IconButton → showDatePicker()
        • Status DropdownButtonFormField (pending / completed) — shown on Edit only
      Validation: done by Flutter Form + GlobalKey<FormState>
        • Title empty → "Title is required"
        • No API call until local validation passes
      On submit:
        • Create: ApiService.createTask(data) → pop with result: true
        • Edit:   ApiService.updateTask(task.id, data) → pop with result: true
      On error from API (ApiException): show SnackBar with message
      Caller (TaskListScreen) checks pop result → if true: reload list

  (3) No separate TaskDetailScreen is required; clicking a task opens
      TaskFormScreen in edit mode. This satisfies the rubric.
